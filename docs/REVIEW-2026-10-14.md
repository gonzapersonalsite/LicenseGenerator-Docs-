# Review — 2026-10-14

## Scope and changes

The review covered license generation and client verification, local keys and history, backup/import, settings, desktop lifecycle, MVVM behavior, localization, documentation, repository organization and release packaging.

- Added optional signed `UserDefined` text with an explicit format-2 contract. Empty custom data preserves the legacy wire format; clients must support format 2 before receiving custom-data licenses.
- Hardened input validation, Unicode handling, portable paths, key access, unique history filenames and bounded archive parsing. Imports preserve existing signing keys and history and reject conflicts before making changes.
- Added atomic settings persistence and recovery, synchronized imported preferences, single-instance storage protection, startup diagnostics and actionable UI error feedback.
- Corrected stale generated output, navigation and pagination behavior, and updated all five documentation languages and the build/release workflow.

The exact compatibility and security rules are maintained in [Architecture](../ARCHITECTURE.md), operational guidance in [Operations](../OPERATIONS.md), and the release changes in the [changelog](CHANGELOG.md). The implementation uses RSA-2048, SHA-256 and PKCS#1 v1.5 signatures; licenses and ZIP backups are not encrypted. Client modification and clock tampering remain outside offline signature protection.
